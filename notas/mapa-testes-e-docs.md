## 5. Answers

### 5.1 How the suites run

**Commands.** `npm test` runs the unit suite and then the e2e suite (package.json:11). The lint is a separate command (package.json:15). README 'Testes' documents `npm test`, `test:unit`, `test:e2e`, `npx playwright install chromium`, `PW_CHANNEL=chrome`, `BASE_URL=…` and the snapshot and golden updates (README.md:36-60); it never mentions `npm run lint`.

**Unit (node:test).** `node --test "test/unit/**/*.test.js"`: only files ending in `.test.js` under `test/unit` (62). Node runs each file in its own process, files in parallel (inferred: node:test default). The unit tests read no network and write no file (measured: no `fetch(` call and no file write under `test/`; the only writer is scripts/capturar-goldens-motor.mjs:11).

**E2E (Playwright), playwright.config.js:**
- `testDir: 'test/e2e'` (8); snapshots at `{testDir}/__snapshots__/{testFilePath}/{arg}{ext}`, no platform suffix (10).
- `fullyParallel: true` (11); no `workers`, no `retries`, no `timeout` set, so Playwright defaults apply: half of the logical cores as workers, 0 retries, 30 s per test (inferred: defaults). No serial describe anywhere (measured: no `describe.configure`/`.serial`). One `test.slow()` (test/e2e/abertura.spec.js:607).
- `forbidOnly` in CI (12); `updateSnapshots`: `'none'` in CI, `'missing'` locally (14); reporter `github` + `list` in CI, `list` locally (15).
- `baseURL`: `process.env.BASE_URL` or `http://localhost:4173/` (17); `locale: 'pt-BR'`, `timezoneId: 'America/Sao_Paulo'` (18-19); `trace: 'retain-on-failure'` (20).
- One project, `chromium` with `devices['Desktop Chrome']` and optional `channel: process.env.PW_CHANNEL` (23). The default viewport of that device is 1280×720 (inferred: Playwright's descriptor), the same width as the page cap.
- `webServer`: `node scripts/serve.mjs` at `http://localhost:4173`, `reuseExistingServer: !process.env.CI`; **absent when `BASE_URL` is set** (24-28). `const PORT = 4173` is hard-coded (3): the config never passes `PORT` to the server.

**Static server, scripts/serve.mjs:** root = the folder above the script, i.e. the checkout the script lives in (8); port `Number(process.env.PORT) || 4173` (9); MIME table for html, js, mjs, css, json, svg, png, ico, anything else `application/octet-stream` (10-19, 31); path-escape guard (24-27); a folder serves its `index.html` (29); `Cache-Control: no-store` (31); 404 "Não encontrado" (34).

**CI, .github/workflows/testes.yml** (runs on every `push` and `pull_request`, lines 3-5; `ubuntu-latest`, `timeout-minutes: 15`, lines 9-10):
1. `actions/checkout@v7` (12); `actions/setup-node@v7` with Node 22 and the npm cache (13-16); `npm ci` (17).
2. **"Lint (ESLint e exportações sem uso)": `npm run lint`** (18-19).
3. "Chromium com as bibliotecas do sistema": `npx playwright install --with-deps chromium`, `timeout-minutes: 4`, `continue-on-error: true` (23-27); if it did not succeed, "Só o Chromium": `npx playwright install chromium` (28-30).
4. "Testes unitários (motor, regras, dados)": `npm run test:unit` (31-32).
5. "Testes E2E (Playwright)": `npm run test:e2e` (33-34).
6. On failure, upload `playwright-report/` and `test-results/` as `relatorio-playwright`, kept 7 days (35-42).

**So:** a green `npm test` = unit + e2e only. The lint is part of CI (step 2, before the tests) but not of `npm test`. Not in CI at all: pgTAP (`npm run test:db`), `npx deno check supabase/functions/meteorologia/index.ts` (README.md:117-118) and test/e2e/publicado.spec.js (skipped without the passwords).

**How long.** Nothing in the repo records suite durations. The only numbers are the CI caps (15 min for the job, 4 min for the browser install: testes.yml:10, 26) and the comment "uns 20 s" for the install (testes.yml:20). Measured for this map on this Mac: unit 5.1 s, ESLint 2.7 s, unused exports 0.6 s; e2e not run.

**There is no deploy workflow:** GitHub Pages publishes `main` directly (README.md:4, 243-244), so the tests gate a merge only through the PR check.

### 5.7 "Tests first, npm test green on every step"

**What a step's PR has to run locally to match CI:** `npm run lint` and `npm test` (lint first, as CI does). For a step with a migration: also `SUPABASE_DB_PASSWORD=… npm run test:db`, only against the preview project (README.md:64-67; scripts/testar-banco.mjs:6), then the matching change in `test/e2e/supabase-falso.js`, because the fake repeats the server's rules by hand and nothing compares the two except for the courses (test/unit/espelho-do-banco.test.js:15-16). For a step that changes the engine's rule: `node scripts/capturar-goldens-motor.mjs` and review the diff (README.md:50-53). For a step that changes what the Escala or the BI shows: `npx playwright test --update-snapshots` and review (README.md:48-49). Optional and manual: `publicado.spec.js` against the preview with real passwords and `--workers=1` (test/e2e/publicado.spec.js:1-5); it hard-codes `#nav button[data-t="esc"]`, `#s-age`, `#inst .cd`, `#form-agenda`.

**What CI runs:** lint, unit, e2e (5.1). It does not run pgTAP, the Deno check or the published-site spec.

**What parallel worktrees should know:**
1. **Port 4173 is shared and silently reused.** The config hard-codes it (playwright.config.js:3) and, outside CI, reuses whatever already answers on it (`reuseExistingServer: !process.env.CI`, :27). If worktree A is serving (its own e2e run, or `npm run serve`) while worktree B runs `npm run test:e2e`, B's tests run against **A's app files**, with no warning. Only one e2e run at a time on a machine, unless a run uses its own server: `PORT=<n> node scripts/serve.mjs` and `BASE_URL=http://localhost:<n>/ npx playwright test` (serve.mjs:9; playwright.config.js:5, 17, 24; the host must stay `localhost` or `127.0.0.1` for the local mode and for `?supabase=teste`, js/config-supabase.js:12-17) (inferred: not executed).
2. **`node_modules` per worktree for the e2e.** `fixtures.js` serves jsPDF, the autotable plugin and supabase-js from `../../node_modules/…` by file path (test/e2e/fixtures.js:15-19), so each worktree needs its own `npm ci`. The unit tests and the lint only need a `node_modules` in some parent folder (measured: both ran from `wt-plano`, which has none, using the parent checkout's).
3. **Playwright browsers are shared** in the user cache (`~/Library/Caches/ms-playwright`, with Chromium already there); they stay valid while `@playwright/test` stays at 1.65.0 (package.json:19).
4. **No shared state between tests:** a new browser context per test, the fake server per context, the clock fixed (test/e2e/fixtures.js:43-47; supabase-falso.js:146). Nothing depends on the real date.
5. **Slow or timing-sensitive tests:** waits of 10 to 20 s for retries (test/e2e/abertura.spec.js:138, 613; compartilhado.spec.js:203; datas-compartilhado.spec.js:94; painel-sessao.spec.js:282, 343), `test.slow()` (abertura.spec.js:607), and `page.waitForTimeout(300)` used to assert that nothing was sent (abertura 4 uses, compartilhado 3, cursos 1). The only flaky test PLAN.md records was the Secretaria redirect race, fixed with `body[data-pronto]` (docs/PLAN.md:331). No retries are configured, so one timeout fails the run.
6. **Snapshots:** locally a missing snapshot is created and the test passes; CI fails on it (playwright.config.js:14). The folder is the spec file's name (:10): renaming `escala.spec.js` or `bi.spec.js` moves its snapshots.
7. **`eslint .` covers the whole folder it runs in** except `node_modules/`, `test-results/`, `playwright-report/` (eslint.config.js:8). A worktree created inside another checkout is linted by that checkout's `npm run lint` too (inferred).

## 7. Implications and options for the redesign (suggestions)

1. **Make the navigation helpers the compatibility layer, first thing in F1.** Rewrite `irPara`, `irParaVista`, `abrir`, `abrirEscala` and one shared `mudarData` in `test/e2e/fixtures.js` against the new shell, keeping their signatures and the old tab keys as names of destinations. Cost: one file, plus the 142 direct date-control uses (21 files) and the 51 direct nav uses (13 files). Risk: the helpers hide a change of meaning (for example `irPara(page, 'dem')` landing on a screen with no editable table) and a test then fails far from its cause.
2. **Replace the "data loaded" wait on `#wins`** by `body[data-pronto]`, which `entrar` already uses (test/e2e/fixtures.js:65, 85; js/main.js:142), before workstream B starts.
